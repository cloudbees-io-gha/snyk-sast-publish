= Snyk SAST scan and publish to Platform

Use this action to scan source code repositories for security vulnerabilities with the Snyk SAST scanner.
The action output can be used as a quality gate in subsequent GitHub Actions steps or jobs.

Snyk SAST (Static Application Security Testing) is a developer-first security solution that scans source code for security vulnerabilities and code quality issues.

Add a Snyk SAST scan to your workflows in CloudBees platform to:

* Detect security vulnerabilities in source code before deployment.
* Identify potential security issues in multiple programming languages including Java, JavaScript, Python, Go, Ruby, PHP, C#, and more.
* Gain insight into code security risks and how to fix issues.
* Ensure compliance with security best practices and industry standards.
* Shift security left by catching issues early in the development lifecycle.

CloudBees platform enables you to run a Snyk SAST scan either implicitly or explicitly.

== Explicit and implicit scan types

An implicit scan is automatically triggered, and an explicit scan is one you configure to be invoked in a step of your workflow.
To learn more about the differences between explicit and implicit scans, refer to link:https://docs.cloudbees.com/docs/cloudbees-platform/latest/actions#security[Security scan actions].

To set up implicit scanning, refer to link:https://docs.cloudbees.com/docs/cloudbees-platform/latest/aspm/implicit-security-analysis[Code and binary security analysis].

== Prerequisites

Set up the CloudBees platform and GHA to work together, providing key features of the platform to GHA workflows. Refer to link:https://docs.cloudbees.com/docs/cloudbees-platform/latest/github-actions/gha-getting-started[Getting started with GHA integration] for more information.

== How the scanner works

The Snyk SAST scanner architectural components are:

* Snyk CLI: The command-line interface that performs the scanning.
* Snyk Code Engine: Analyzes source code using machine learning and symbolic execution.
* Snyk Knowledge Base: Contains security rules and vulnerability patterns across multiple languages.
* Snyk API: Communicates scan results to the Snyk platform for centralized management.

The scanning process is as follows:

. The Snyk SAST scanner identifies source code files in your repository.
. Source code is parsed and analyzed against Snyk's security vulnerability database.
. Security vulnerabilities and code quality issues are identified using advanced pattern matching and data flow analysis.
. Results are reported with severity levels, detailed descriptions, and remediation guidance.
. The scan results are uploaded to the Snyk platform (if configured).
. Results are made available as actionable outputs for quality gates and downstream workflow steps.

NOTE: For more information about Snyk SAST, refer to the link:https://docs.snyk.io/products/snyk-code[Snyk Code documentation].

== Inputs

[cols="2a,1a,1a,3a",options="header"]
.Input details
|===

| Input name
| Data type
| Required?
| Description

| `snyk-token`
| String
| Yes
| The Snyk API token for authentication.

| `org-id`
| String
| Yes
| The Snyk organization ID.

| `ref`
| String
| No
| Specify the ref to be checked out and scanned.

| `workspace-dir`
| String
| No
| The file path of the code to be scanned.

|===

== Outputs

[cols="2a,1a,4a",options="header"]
.Output details
|===

| Output name
| Data type
| Description

| `critical-count`
| String
| The number of *Critical* severity issues discovered during the scan.

| `very-high-count`
| String
| The number of *Very High* severity issues discovered during the scan.

| `high-count`
| String
| The number of *High* severity issues discovered during the scan.

| `medium-count`
| String
| The number of *Medium* severity issues discovered during the scan.

| `low-count`
| String
| The number of *Low* severity issues discovered during the scan.

|===

IMPORTANT: This action uses GitHub OIDC authentication to securely communicate with CloudBees platform.
Be sure to set permissions to `id-token: write` in your workflow.

== Usage examples

The following is a basic example of using this action:

[source,yaml]
----
    permissions:
      id-token: write
      contents: read
    steps:
      - name: Scan with Snyk SAST
        uses: cloudbees-io-gha/snyk-sast-publish@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}

----

=== Using the action output

You can use the output values from this action in downstream steps and jobs.
The following example uses the action output in a downstream step of the same job:

[source, yaml,role="default-expanded"]
----
name: my-workflow

on:
  push:
    branches:
      - main

permissions:
  contents: read
  id-token: write

jobs:
  snyk-sast-scan-job:
    runs-on: ubuntu-latest
    steps:
      - name: Check out source code
        uses: actions/checkout@v2

      - id: snyk-sast-step
        name: Snyk SAST Scan
        uses: cloudbees-io-gha/snyk-sast-publish@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}

      - name: Source dir examine
        run: |
          docker run --rm -v "${{ github.workspace }}:/work" -w /work golang:1.20.3-alpine3.17 ls -latR /work

      - id: print-outputs-from-snyk-sast-step
        name: Print outputs from the upstream Snyk SAST Scan step
        run: |
          # Printing all outputs
          echo "Outputs from upstream Snyk SAST Scan step:"
          echo "Critical count: ${{ steps.snyk-sast-step.outputs.critical-count }}"
          echo "Very high count: ${{ steps.snyk-sast-step.outputs.very-high-count }}"
          echo "High count: ${{ steps.snyk-sast-step.outputs.high-count }}"
          echo "Medium count: ${{ steps.snyk-sast-step.outputs.medium-count }}"
          echo "Low count: ${{ steps.snyk-sast-step.outputs.low-count }}"
----

=== Full workflow and run example

The following GHA workflow example scans a source code repository with Snyk SAST scanner.

.Example GHA workflow YAML file
[.collapsible]
--

[source, yaml,role="default-expanded"]
----
name: Snyk SAST scan

on:
  push:
    branches:
     - main

permissions:
  id-token: write
  contents: read

jobs:
  snyk-sast-scan:
    runs-on:
     ubuntu-latest
    outputs:
      snyk-sast-job-output-critical: ${{ steps.snyk-sast-step.outputs.critical-count }}
      snyk-sast-job-output-very-high: ${{ steps.snyk-sast-step.outputs.very-high-count }}
      snyk-sast-job-output-high: ${{ steps.snyk-sast-step.outputs.high-count }}
      snyk-sast-job-output-medium: ${{ steps.snyk-sast-step.outputs.medium-count }}
      snyk-sast-job-output-low: ${{ steps.snyk-sast-step.outputs.low-count }}
    steps:

      # Checkout code
      - name: Checkout repository code
        uses: actions/checkout@v4

      # Print run info
      - name: Print run info
        shell: bash
        run: |
          echo "Ref name is $GITHUB_RUN_ID"
          echo "Source is ${{ github.server_url }}/${{ github.repository }}"
          echo "Subject is $GITHUB_WORKFLOW_REF|${{ github.run_id }}|${{ github.run_attempt }}|${{ github.run_number }}"
          echo "Job is $GITHUB_JOB"

      # Run Snyk SAST scan
      - name: Snyk SAST scan
        id: snyk-sast-step
        uses: cloudbees-io-gha/snyk-sast-publish@v1
        with:
          snyk-token: ${{ secrets.SNYK_TOKEN }}
          org-id: ${{ vars.SNYK_ORG_ID }}

      - name: Source dir examine
        run: |
          docker run --rm -v "${{ github.workspace }}:/work" -w /work golang:1.20.3-alpine3.17 ls -latR /work

      - id: print-outputs-from-snyk-sast-step
        name: Print outputs from the upstream Snyk SAST Scan step
        run: |
          # Printing all outputs
          echo "Outputs from upstream Snyk SAST Scan step:"
          echo "Critical count: ${{ steps.snyk-sast-step.outputs.critical-count }}"
          echo "Very high count: ${{ steps.snyk-sast-step.outputs.very-high-count }}"
          echo "High count: ${{ steps.snyk-sast-step.outputs.high-count }}"
          echo "Medium count: ${{ steps.snyk-sast-step.outputs.medium-count }}"
          echo "Low count: ${{ steps.snyk-sast-step.outputs.low-count }}"

----
--
